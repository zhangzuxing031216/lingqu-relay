# 安全

## 1. 威胁模型

| 威胁 | 入口 | 后果 | 缓解 |
|---|---|---|---|
| 密钥泄露 | Git/日志/前端/截图 | 被盗刷/账单 | 不进仓库、打码、轮换 |
| 注册刷号 | 公开注册 | 垃圾账号/额度 | 验证码、限流、关注册 |
| API 滥用 | 公开 key | 额度耗尽 | 令牌限额、分组、限流 |
| 后台爆破 | 登录页 | 接管 | 强密码、失败限制、IP 白名单 |
| 上游 key 被盗 | 服务器/备份 | 上游账单 | 最小权限、轮换、加密备份 |
| 支付伪造 | 回调 | 虚假到账 | 验签、订单去重、小额测试 |
| 数据泄露 | 备份/DB | 用户信息 | 600 权限、加密、异地私有存储 |
| DDoS | 443 | 全站不可用 | CDN/云防护、限流 |

## 2. 密钥管理

**绝对不进 Git**：

- 上游 API key
- new-api 管理员密码
- 支付 `pid` / `key`
- `lq_captcha.secret`
- 数据库/备份
- SSH 私钥
- `.env`

做法：

1. 用 `.env`（已 gitignore）或 systemd `EnvironmentFile`。
2. 只给必要的人。
3. 定期轮换；泄露立即吊销。
4. 日志里打码：`sk-...abcd`。
5. 截图前打码。

检查仓库有没有混入：

```bash
git grep -nE 'sk-[A-Za-z0-9]{20,}|BEGIN (RSA|OPENSSH) PRIVATE KEY|password\s*=' || true
```

## 3. 网络

```bash
# 只看监听
ss -lntp

# 期望：22、80、443 对外；3000/3100 只 127.0.0.1
```

- 云安全组只放行 22/80/443。
- 3000/3100 不要绑 `0.0.0.0`。
- 不用时关掉 3000/3100 的公网规则（如果云厂商有）。
- 可选：只允许自己的 IP 访问 SSH。

UFW 示例（谨慎，先确认 SSH 端口）：

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
ufw status
```

> 在云服务器上改防火墙前，确认控制台 VNC 可用，避免把自己锁在外面。

## 4. SSH

```bash
# /etc/ssh/sshd_config
PermitRootLogin prohibit-password
PasswordAuthentication no
PubkeyAuthentication yes
```

改完：

```bash
sshd -t
systemctl reload ssh
```

> 先确认密钥能登录，再禁用密码。

## 5. 后台

- 管理员密码 ≥16 位，唯一。
- 不在浏览器保存密码（共享机器）。
- 开启登录失败限制。
- 后台路径不要公开分享。
- 定期检查管理员列表。
- 不给普通用户管理员权限。

## 6. API 令牌

- 一个用户一个令牌，不共用。
- 设额度上限/过期时间。
- 按分组限制模型。
- 泄露立即删令牌。
- 不在前端 JS 里写 key。

## 7. 注册与滥用

- 默认关闭公开注册；需要时再开。
- 验证码网关 + 同 IP 限流。
- 新用户不送大额额度。
- 监控异常注册/调用。
- 保留封禁/申诉流程。

## 8. 支付

- 只信服务端验签，不信前端“支付成功”。
- 回调必须校验签名/金额/订单号。
- 订单号幂等，防重复到账。
- 支付密钥只放后台/环境变量。
- 先小额测试，再放量。
- 保留退款/争议处理记录。

## 9. 备份

- 备份含用户数据，按敏感数据管理。
- 文件权限 600，目录 700。
- 异地备份用私有 bucket / 加密磁盘。
- 定期演练恢复。
- 不要把备份放公开的 Web 目录。
- 不要把 `.env`、`lq_captcha.secret` 打进公开备份。

## 10. Caddy 安全响应头（可选）

在站点块里加：

```text
header {
    X-Content-Type-Options nosniff
    X-Frame-Options DENY
    Referrer-Policy strict-origin-when-cross-origin
    -Server
}
```

> 如果前端需要被 iframe 嵌入，不要设 `X-Frame-Options DENY`。
> CSP 要按实际静态资源配，别直接抄。

## 11. 日志

- 不记录密码、token、完整 key。
- 访问日志保留 7–30 天，按隐私要求。
- 日志目录不要公开。
- 分享日志前排错信息打码。

## 12. 上游条款与法律

- 只转卖被允许转卖的服务。
- 遵守上游 rate limit/使用政策。
- 不提供违法内容。
- 国内服务器注意备案/内容合规。
- 有明确的用户协议、隐私政策、退款规则。

## 13. 事件响应

1. **止损**：吊销 key、关注册、停服/封 IP。
2. **取证**：保留日志、DB 快照，不破坏现场。
3. **评估**：影响范围、账单、用户数据。
4. **修复**：换密钥、打补丁、改配置。
5. **复盘**：原因、时间线、改进项。
6. **通知**：如涉及用户数据/支付，按法律要求通知。

## 15. 漏洞报告

如果你发现本模板的安全问题，请不要公开贴出可利用细节。
开 Issue 说明影响范围，或私下联系维护者。不要拿真实用户数据/生产 key 做测试。
